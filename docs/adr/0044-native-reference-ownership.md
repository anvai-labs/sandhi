# ADR-0044: Native reference issuer ownership

Status: implementation checkpoint; integration and independent review required.

A virtual key authorizes its declared model/backend, not every object held by the backend's shared provider credential. A compatible route pin proves transport affinity. It does not prove that a response ID, saved item, encrypted reasoning, file, cache or container belongs to that key. Two callers with independent compatible pins previously could name the same provider object.

The HTTP gateway now requires a durable issuer proof before admitting a native reference. The proof associates a reference-kind/digest with the authenticated virtual-key ID, subject, group and upstream binding, and with the frozen backend ID/revision, credential reference and applicable generation, actual credential/account/endpoint fingerprint, model, endpoint family/profile and source convention. Caller session hints, metadata and headers provide no ownership authority. A live proof cannot transfer to a different owner. A resource ID has one owner per binding; an ambiguous duplicate ID refuses delivery. Self-contained encrypted reasoning, thinking signatures and redacted blocks can be independently returned to multiple owners: each gets its own proof only after its own source issuance. Knowing or submitting another owner's opaque value never creates that proof.

The effective selected backend payload is inspected after canonical encoding, reserved-field removal and the frozen cache plan, before pin confirmation or execution admission. This includes references carried in the selected `sandhi_extensions` bucket across ingress dialects; inactive buckets have no authority. Fidelity refusals remain HTTP 400, while missing ownership proof is HTTP 403. Discovered state also requires the existing established compatible logical session. Operator output defaults precede candidate preflight; explicit caller limits are preserved. Count-only requests do not acquire generation defaults, pins, execution admission or issuance proof.

Native provider output supplies proof. Compatible buffered native envelopes and complete native SSE frames are inspected before forwarding; their IDs and opaque state commit to the registry first. A server-private response extension distinguishes native emission from rendered portable output. This is not a wire header. Rendered IDs are not imported as provider references. Fragmented Messages signatures are held within a fixed budget until their complete value can be committed before the first signature fragment is exposed. The original native bytes and event order remain intact.

The complete private execution owner initializes the registry automatically from its actual original single-file ledger path before publication. Binary and public library serving use this same initializer; no separate public registry option or path is required. Malformed/read-only registry storage refuses serving before bind, while read-only app construction can expose health/readiness probes. The registry uses the original store file and stores only digests, a bounded kind and expiry. Its primary key includes the owner; a partial unique index enforces single-owner resource IDs while permitting separate owner rows for the three self-contained kinds. It has a 100,000-row global bound, 4,096 rows per authenticated owner, at most 128 unique references per request/response, an eight MiB frame/signature retention budget including frame overhead, four nonqueued storage slots and at most 256 expired-row deletions per issuance. Up to 128 deletions prioritize the current owner; up to 128 indexed deletions target the resource IDs actually reissued by this source, with any remaining allowance spent on global expiry. Cleanup and fresh issuance share one transaction; authorization remains a pure lookup. Proof expires within 24 hours and no later than the key. Ordinary credentials also cap proof at their issuing lease expiry. Only the existing account-fenced Codex contract omits credential generation and old access-token expiry: the actual account/origin/static-header fingerprint and backend/revision/profile/model remain fenced, and every new request must have a current credential lease. Unleased account-only Codex handles refuse HTTP admission without changing the legacy route fingerprint. Expiry limits this gateway's authorization; it does not assert provider-side resource deletion. Capacity, unavailable storage, expiry, changed bindings and unknown references fail closed.

Proof is separate from execution evidence. It creates no dispatch permit, final usage, zero usage, lease release or receipt. A proof-write failure stops reference delivery and forbids automatic replay. While the client remains connected, streaming delivery drains the same bounded source so its existing accounting owner can retain the real final or incomplete outcome. Buffered failures retain the source result already recorded. Disconnect/cancellation can still leave unknown liability; no final usage is inferred. No deadline, retry policy or provider send is added.

New same-owner native state works across restart while its binding and proof remain valid. Known references from before this registry existed are unverified, even when an old route pin survives. Start a fresh materialized session rather than guessing their issuer. External resources without server-observed proof remain unsupported until an explicit operator adoption contract exists; this checkpoint adds no adoption endpoint or cache CRUD. Constrained Codex keeps its existing materialized-input requirement: owned encrypted reasoning can replay, while server continuation/item lookups still refuse.
