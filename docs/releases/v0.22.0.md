# Sandhi 0.22.0: exact thinking capability and durable evidence

Status: **source candidate, 2026-11-19**. This guide describes the reviewed source candidate.
Promotion, immutable publication, deployment, and live Victor/RepoReel qualification remain
separate gates and are not claimed here.

## Why

Reasoning controls were previously inferred from provider names and model prefixes, and the
DS3 timeout investigation showed that advertised stream limits and retained transport evidence
did not say enough to diagnose a failed request. Both problems need exact model facts and
durable observations, without changing the OpenAI, Anthropic, Responses, or Gemini SDK request
shapes used by callers.

This release makes model thinking capability explicit, makes transport evidence observable, and
keeps unresolved accounting liability visible. It is a coordinated pre-GA cutover: public chat
contract version remains `1`, and old ledgers are rebuilt offline rather than carrying runtime
compatibility branches into the GA baseline.

## Thinking contract

The neutral contract has one semantic `thinking` object:

```json
{
  "model": "qwen3.8-plus",
  "thinking": {"enabled": true, "effort": "medium"},
  "messages": [{"role": "user", "content": "hello"}]
}
```

Omitting `thinking` uses the model default. `{"enabled": false}` is the only disable operation
and requires the model to advertise `can_disable`. Effort and budget controls require exact
model capability declarations; `"none"` is not an effort alias. A model that advertises both
controls must explicitly allow their combination. An explicit enabled request must carry an
advertised effort or budget control; use omission to select the model default. Removed neutral
pre-GA fields such as top-level `reasoning_effort` are rejected instead of silently ignored.

Backend model registration may omit `thinking` for a model that cannot configure it; omission
normalizes to the same fail-closed `{"supported": false}` descriptor as an explicit unsupported
declaration. Discovery and public catalog/binding descriptors always report a sanitized semantic
thinking descriptor for every model. OpenAI and Anthropic discovery expose it as `thinking`;
Gemini's native SDK reserves `thinking` for a boolean, so its semantic object is exposed as
`sandhi_thinking`. The descriptor contains only semantic capability facts: supported controls,
exact effort values and default, budget bounds, and whether disable/combination is allowed. The
transport encoding is omitted from every public model descriptor and is validated against the
selected endpoint family.

Public SDK dialects remain stable:

| Ingress dialect | Native request spelling |
|---|---|
| OpenAI Chat | top-level `reasoning_effort`, plus qualified Qwen/ZAI controls |
| OpenAI Responses | `reasoning.effort` (`"none"` maps to semantic disable) |
| Anthropic Messages | native `thinking` object |
| Gemini | `generationConfig.thinkingConfig.thinkingBudget` |

Duplicate or conflicting spellings are rejected. On egress, a closed encoding profile restores
the exact source spelling. A codec that cannot express a control cannot advertise that control.
Provider names, OpenAI compatibility, and model-name similarity never establish capability.

## Streaming evidence and accounting

Every tracked admission now freezes the effective setup, idle, and body policy (or buffered
duration) plus the configured upstream host. A physical attempt records whether response headers
and a stream event were observed, TTFT when available, provider status/request ID when
available, exact timeout phase (`setup`, `idle`, or `body`), and a bounded error class/subtype.
The DS3-style
pre-header timeout now remains a setup timeout instead of degrading to `unknown`.

The effective limits advertised through model discovery are the same limits applied by raw and
transparent transport. Qualification tests cover policy-receipt equivalence, setup expiration,
idle expiration, body expiration, and heartbeats that cannot reset an absolute body deadline.

When final provider-reported usage is unavailable, Sandhi records a stable unresolved reason:

- `transport_evidence_incomplete` when physical evidence is missing or incomplete;
- `provider_usage_unavailable` when the terminal exists but final usage does not.

The reservation stays held. Recovery does not invent a zero charge, replay inference, or switch
providers. `/readyz` returns `503 durable_accounting_recovery_unresolved` while initialization,
durable recovery, unresolved rows, or retained settlement work remains incomplete.

## Offline pre-GA ledger swap

Sandhi 0.22.0 does not upgrade a live ledger in place. Stop every writer for the ledger set,
then build and validate a clean copy:

```bash
python3 scripts/rebuild_prega_ledger.py \
  --source /path/to/original.db \
  --output /path/to/sandhi-0.22.0.db \
  --manifest /path/to/original.rebuild.json
```

The helper never opens the original SQLite set through SQLite: it copies the main database plus
any WAL/SHM sidecars to private staging, verifies the original byte-for-byte before and after,
makes a consistent backup, changes old execution contexts and attempt evidence to the clean
version-1 representation inside that copy, and writes a SHA-256 manifest with the immutable
source-snapshot and reservation inventory.
Historical streaming contexts receive `streaming_legacy_unavailable`; historical buffered
contexts receive `buffered_legacy_unavailable`; missing progress facts are represented by absent
fields (unknown) instead of being inferred as false. When a `backends` table is present, legacy
model definitions are migrated conservatively to `thinking: {"supported": false}`; an operator
must later re-register any model that intentionally supports thinking. A registry stored outside
the rebuilt ledger must be rebuilt or re-registered separately before traffic. The helper is
idempotent and fails closed on malformed evidence, broken context/attempt linkage, or reservation
drift.

After all instances have stopped, atomically replace the old files with the validated rebuilt
copies, start only Sandhi 0.22.0, verify `/readyz`, unresolved-liability counts, reservation
conservation, and the failed-request evidence, then resume traffic. Keep the original database
and manifest immutable. CSV is suitable only as a derived human-readable export; it is not the
durable transfer format.

## Consumer release pins

Victor should consume sanitized Sandhi discovery for `supports_reasoning_effort` and fail closed
when the model or capability is absent. Its SDK request shape does not need a RepoReel migration.
The coordinated recommendation is Victor `0.32.0` with an exact Sandhi Gateway `0.22.0` pin;
RepoReel then pins the tested Victor release. Do not infer Qwen capability from the OpenAI wire
dialect or from a provider class.
