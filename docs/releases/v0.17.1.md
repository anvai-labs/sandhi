## Correction to the unpublished 0.17.0 tag

The immutable `v0.17.0` source tag is retained. Its release workflow built the
wheels and npm artifacts, but both binary smoke jobs refused startup because the
fixture omitted the mandatory durable store. All registry publishers and GitHub
release creation were skipped; no partial package publication is claimed.

This release provides a private ordinary-file ledger and empty credential store
for the isolated smoke, and runs that actual binary smoke in ordinary CI before
release tagging. It also corrects source finality for standard and terminal-choice
Chat streams: additional output after final totals cannot qualify a final charge;
the original observation stays partial. Harmless repeated identical totals retain
their existing idempotent meaning. Independent review, full CI, protected promotion,
exact-main CI and all-target artifact verification completed for this release.

The coordinated Victor consumer requires the exact `sandhi-gateway==0.17.1` pin
and published-wheel qualification before its consumer PR merges. A source pin
alone does not establish consumer adoption or deployment.

## Upgrade the existing installation

1. **Quiesce all old writers and back up the complete store** using the established
   SQLite/backup procedure. Retain the original deployment, auth/TLS/vault settings
   and an offline recovery plan. Do not run old and new writers against the same
   upgraded file, and do not treat an old binary as a safe downgrade onto new evidence.
2. **Set `SANDHI_STORE` to that same ordinary file.** Memory/URI forms are refused.
   Leave `SANDHI_LEDGER_SHARDS` unset or set exactly `1`. Multiple serving shards
   require an explicit offline topology migration before starting this version;
   startup rejects unsupported topology before ledger open/migration. Do not evade
   refusal with a fresh empty ledger: that would discard budget and recovery authority.
3. **Remove `SANDHI_BUFFERED_ACCOUNTING` completely.** Any supplied value, including
   `off` and `tracked`, refuses startup. Every supported HTTP generation path now
   uses the existing durable paired owner. Block and Warn both require working
   storage and preserve unknown liability; Warn only relaxes a soft cap.
4. **Move Victor to its coordinated 0.29.0 contract** and exact 0.17.1 binding pin.
   Physical calls have no hidden retries, gateway calls use an explicit client
   dialect/peer role, and cache intent is compiled once by the server. Provider FFI
   shares strict source/fidelity semantics but does not become a SQLite ledger owner.
5. **Review operator defaults.** Missing chat output limits receive 4,096 by default;
   `SANDHI_DEFAULT_MAX_OUTPUT_TOKENS` changes that policy and an explicit model ceiling
   may narrow it. Explicit caller limits stay explicit. Bounded stream source defaults
   are 30 s setup / 90 s idle / 180 s body under a 240 s ceiling; declared route policy
   can override them. These are estimates/lifetime controls, not physical token bounds;
   constrained Codex retains its codec's omitted wire maximum. Default injection uses
   canonical encoding, preserving compatible native controls or refusing explicitly.
   Native Text Completions defaults to 16 when omitted; Embeddings reserves input only.
6. **Restart using the original state.** The binary and public Rust `serve*` functions
   initialize one owner, native-reference metadata, recovery and bounded shutdown
   supervision. There is no separate registry initializer or second database. A
   read-only app can expose operator probes but remains unready and refuses generation.
7. **Check contract, readiness and one representative request separately.** With usual
   operator authentication, `/admin/version` must report
   `capabilities.execution_accounting == "paired_durable_v1"`. `/readyz` separately
   supplies a lifecycle snapshot. Neither proves live SQL/provider health, available
   budget or a request receipt. Inspect the request's original source/attempt/paired
   receipt and delivery outcome through the existing evidence tools.

## What must survive migration

Existing limits/windows/policies, spend, live holds, deduplication history, reservation
IDs and compatible route pins stay on the same file. A configured provider label is
not budget authority: the backend's stored immutable `upstream_budget_scope` remains
authoritative, including an old family-named bucket. Do not regroup historical spend
or create new allowance by renaming a provider.

Older rows acquire no invented context, attempt, cache weight or receipt. Historical
unpaired expiry keeps its previous behavior. New unknown paired usage remains held
through expiry/restart; qualified final source usage settles both legs atomically
under the original frozen charge. Receipt failure can recover accounting without
another model call. Failed output delivery can still have a valid source charge.

Supported native IDs/opaque state need proof from this gateway's observed source
issuance for the same authenticated owner and compatible binding. New valid proof
survives restart; pre-registry references do not become trusted merely because an
old route pin survives. Start a fresh materialized session when provenance is absent.
No implicit adoption of externally created cache/file/retrieval resources is provided.
See [ownership limits](../adr/0044-native-reference-ownership.md).

Usage/chat wire schema remains **v1**, with additive chat minor **13**. Stricter
0.17.1 execution semantics, gateway peer/count conventions and persisted diagnostic
evidence versions have their own roles; they do not authorize rewriting old records
or claiming a new wire major.

all four client dialects and both delivery modes. The successful Messages portable
profile explicitly disables thinking. Default native-state refusals remain evidence
of the fidelity boundary, not permission to drop state or replay inference. Native
Codex uses operator-configured account/expiry fences; these are not independent
cryptographic identity verification or live subscription renewal acceptance. GLM's
Bearer Coding Plan API credential is distinct from first-party Claude Pro/Max OAuth,
for which no supported Sandhi consumer-subscription relay is advertised.

Current Linux reliability acceptance preserves the original deadlines and accounting
assertions. Historical Python TLS child exits, shutdown timing and accounting waits
remain unexplained; successful current probes do not establish their causes fixed
or generalize to untested platforms. No USD saving, billing equivalence, universal
cache hit, external-resource lifecycle or arbitrary native-extension support follows
from these results.


Native-reference metadata workers are owned through actual completion, including

budget and shutdown deadline; later frames cannot extend either. Native bytes
wait for committed proof, and storage refusal retains source accounting without
