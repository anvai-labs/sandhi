# Sandhi 0.22.1: release wheel-tag verification recovery

Status: **source candidate**. This release is reserved for a focused recovery from the
unpublished immutable [`v0.22.0`](https://github.com/anvai-labs/sandhi/releases/tag/v0.22.0)
tag after its release workflow failed closed.

The 0.22.0 Linux wheel jobs built versioned `sandhi-gateway` wheels successfully, but the new
metadata guard incorrectly assumed that a wheel filename must encode exactly one tag. Maturin's
manylinux2014 compatibility spelling combines aliases in the filename, while the internal
`WHEEL` metadata carries the full `cp311-abi3-*` tag set. The guard rejected those valid wheels.
The macOS binary job also encountered a transient GitHub artifact-upload timeout. All GitHub,
PyPI, crates.io, and npm publishers were skipped; no 0.22.0 publication is claimed.

This release keeps the failed tag immutable and changes only the release verification logic:
the guard now expands every Linux filename alias to its full interpreter/ABI-qualified internal tag,
then rejects duplicate, missing, or extra tags. A regression covers the exact
`manylinux2014_x86_64.manylinux_2_17_x86_64` filename produced by the release container. All
workspace, binding, crate, lockfile, and npm identities are staged as `0.22.1`.

## Validation

- `cargo fmt --check`
- `python3 -m pytest tests/release -q`
- `python3 scripts/check-release-version.py --sync`
- `python3 scripts/check-release-version.py --version 0.22.1`

These checks qualify this source candidate only. Exact-source CI, independent review, protected
promotion, exact-main CI, immutable tagging, all-target publication, and consumer pinning remain
separate gates. After publication, coordinated consumers should pin `sandhi-gateway==0.22.1`.
