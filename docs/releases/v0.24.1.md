# Sandhi 0.24.1: per-request ZAI effort and lock remediation

Status: **source candidate**. This patch release carries the reviewed ZAI per-request
reasoning-effort routing fix and the consistent binding-lock remediation for the `url` security
advisory.

An OpenAI-compatible request carrying only `reasoning_effort` is admitted as thinking provenance
for a ZAI-capable backend. The `low`, `high`, and `max` efforts can change between requests on the
same logical route, virtual key, profile, model, backend, and ledger, with the exact effort and ZAI
enabled-thinking shape asserted upstream.

A semantic thinking control now forces typed translation even when ingress and upstream families
match. This prevents transparent forwarding from bypassing vendor-specific thinking encoding.
Consequently, native Gemini HTTP and typed FFI execution both emit the canonical REST
`generationConfig.thinkingConfig.thinkingLevel` field after exact model admission.

The root, Python-binding, and Node-binding lockfiles select `url` 2.5.9 and its required
`form_urlencoded` 1.2.3 dependency. No dependency edges or reverse-dependency selections change.
